# FlowDesk Web

## Stack

- Next.js **16.2.10** (App Router) + React 19 + TypeScript. This is not the Next.js from your training data — read the vendored docs (see top banner) before writing code.
- Tailwind CSS **v4** via `@tailwindcss/postcss` (no `tailwind.config`; theme lives in `src/app/globals.css` using CSS-first config). Do not write `@apply`/`@layer` like v3.
- pnpm is the package manager (`pnpm-lock.yaml` present; `pnpm-workspace.yaml` only configures ignored build deps).

## Commands

- `pnpm dev` — dev server on http://localhost:3000
- `pnpm lint` — eslint (flat config, `eslint.config.mjs`)
- `pnpm build` — the only typecheck gate; there is **no** `typecheck` script and **no test framework**.
- No lint-staged, CI workflows, or pre-commit hooks in this repo.

## Architecture — read this first

- **UI-only prototype.** Every page renders static mock data; there is no backend wired in yet. All data lives in `src/lib/*-data.ts` (e.g. `dashboard-data.ts`, `projects-data.ts`), which also define the domain types (`TaskStatus`, `ProjectStatus`, etc.). Feature components import types/constants from these modules.
- **Every backend seam is marked** with a `// TODO: Connect ... API` comment in the data modules and components. When adding a feature, follow that pattern — do not invent a real API or hook up services silently.
- Pages in `src/app/**/page.tsx` are thin wrappers over a page component in `src/components/<feature>/`. Each feature owns its folder (e.g. `tasks/`, `workflows/`, `ai-agents/`). Shared primitives live in `src/components/ui/` (shadcn-style, built on `cva`, `clsx`, `tailwind-merge`).
- **Role-based rendering** is the main interactivity: `UserRole = "super_admin" | "admin" | "member"` from `src/context/role-context.tsx` (defaults to `"admin"`, mock only). `getNavigationForRole()` in `src/lib/navigation.ts` decides which routes/sidebar items each role sees — new pages should be registered there.
- **Socket wiring is expected, not done.** `src/lib/socket.ts` creates a `socket.io-client` instance pointed at `process.env.NEXT_PUBLIC_BASE_URL` (default `http://localhost:5000`). `src/context/SocketContext.tsx` is an empty stub — do not treat it as a working provider.
- Path alias: `@/*` → `src/*` (set in `tsconfig.json`). `CLAUDE.md` just imports `AGENTS.md`.

## Environment / setup gotchas

- `.env.local` is **gitignored** but required for backend-adjacent work. It contains `NEXT_PUBLIC_BASE_URL=http://localhost:5000`. The socket client falls back to that URL if unset.
- `next-env.d.ts` is gitignored (generated by Next on `dev`/`build`); don't hand-edit it.
- Some files (e.g. `role-dashboard.tsx`, `agent-details.tsx`) are written as single long lines — match the existing style rather than reformatting.
